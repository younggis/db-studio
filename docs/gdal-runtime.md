## Reference CMake configuration (not used for the vcpkg build)

This direct-from-source CMake example records the driver selection that was initially considered. It has not been used for the current build; the actual build uses the vcpkg manifest and installed package graph. In GDAL v3.12.2, GeoPackage depends on SQLite plus the OGR SQLite driver; PostgreSQL/PostGIS depends on PostgreSQL and PGDump.

```powershell
cmake -S . -B build-reduced -G Ninja `
  -DCMAKE_BUILD_TYPE=Release `
  -DCMAKE_INSTALL_PREFIX=install-reduced `
  -DBUILD_APPS=ON `
  -DGDAL_BUILD_OPTIONAL_DRIVERS=OFF `
  -DOGR_BUILD_OPTIONAL_DRIVERS=OFF `
  -DOGR_ENABLE_DRIVER_SHAPE=ON `
  -DOGR_ENABLE_DRIVER_GEOJSON=ON `
  -DOGR_ENABLE_DRIVER_KML=ON `
  -DOGR_ENABLE_DRIVER_TAB=ON `
  -DOGR_ENABLE_DRIVER_SQLITE=ON `
  -DOGR_ENABLE_DRIVER_GPKG=ON `
  -DOGR_ENABLE_DRIVER_PGDUMP=ON `
  -DOGR_ENABLE_DRIVER_PG=ON `
  -DGDAL_ENABLE_DRIVER_PDF=OFF `
  -DOGR_ENABLE_DRIVER_MYSQL=OFF `
  -DGDAL_USE_POPPLER=OFF `
  -DGDAL_USE_MYSQL=OFF `
  -DGDAL_USE_SQLITE3=ON `
  -DGDAL_USE_POSTGRESQL=ON

cmake --build build-reduced --config Release --parallel
cmake --install build-reduced --config Release
```

This example is not evidence of a successful direct CMake configuration and does not describe the vcpkg candidate below. That candidate has a separate manifest/build record, driver/import inspection, bundle hashes, and completed host GIS/PostGIS integration checks. It remains staged separately pending clean-Windows CRT validation and license/source review; technical test results do not provide license clearance.

The driver selection and dependency relationships were checked against the [GDAL 3.12.2 CMake configuration](https://github.com/OSGeo/gdal/blob/v3.12.2/gdal.cmake), its [OGR driver declarations](https://github.com/OSGeo/gdal/blob/v3.12.2/ogr/ogrsf_frmts/CMakeLists.txt), and the [GDAL build guide](https://gdal.org/en/stable/development/building_from_source.html).
