## 已落实的实现差异修正

- Shapefile 与 TAB 输出显式传 UTF-8 和格式约束选项，TAB 对用户编码覆盖仅处理 staging sidecars。
- CSV 按 BOM 识别 UTF-8/UTF-16LE/UTF-16BE 并进行完整严格验证；无 BOM 文件仅在样本候选置信度 ≥90%、领先次选 ≥15 个百分点且全文件严格解码通过时提供启发式候选，否则仍须人工选择；编码覆盖写入临时 UTF-8 副本且不改原始文件。严格解码不能证明语义正确，启发式结果仍要求预览。PostGIS CSV 导入设 `LAUNDER=NO`，保留源字段名中的大小写和标点。
- Shapefile 输入覆盖改用 `-oo ENCODING=...`，不再让全局 `SHAPE_ENCODING` 污染输出；DBF 编码抽样按真实字段偏移读取。
- CRS 读取兼容 OGR 嵌套 WKT；未知源 CRS 不默认 EPSG:4326。
- RFC 7946 GeoJSON/KML 不允许 projected target 被误标成地理输出。
- operation report 对格式约束提供可见警告；GUI 与 CLI 共用 service。
- PostGIS 集成实测发现 TAB `UTF-8` charset mapping 拼写缺陷，已改为准确的 MapInfo key 并增加测试。

## 2026-11-22 Oracle spatial-index opt-in update

The general note below that spatial indexes are unavailable is now superseded for Oracle new-table imports only. Core, CLI, and desktop IPC expose an explicit opt-in that registers `USER_SDO_GEOM_METADATA` and creates a `MDSYS.SPATIAL_INDEX`; isolated Oracle 23c Core and CLI integration both verified VALID metadata/index state and zero cleanup residue. It requires the current user's schema, simple uppercase table/geometry identifiers, at least one XY geometry, a common positive SRID, and a known extent. The generated metadata uses a 5% extent margin and 0.05 tolerance, which users should review against source precision. Append/overwrite index creation and MySQL/MariaDB/SQL Server index creation remain open. Evidence: [Oracle spatial-index test](test-report.md#2026-11-22-oracle-sdo-spatial-index-opt-in) and [machine report](../.cache/gis-roundtrip/oracle-gis-file-roundtrip-20261121.json).

## 2026-11-22 MySQL/MariaDB and SQL Server spatial-index update

The note above described the state immediately after Oracle support and is superseded for MySQL, MariaDB, and SQL Server by the later implementation. MySQL/MariaDB now create opt-in SPATIAL indexes for new tables after validating positive SRID and all geometries non-NULL; the destination spatial column is NOT NULL. MySQL's native SRID column restriction rejects mismatches; MariaDB uses `REF_SYSTEM_ID` metadata plus an enforced `CHECK (ST_SRID(geom) = n)` because metadata alone does not reject mismatched values. SQL Server now creates geometry/geography spatial indexes for new tables by promoting the staged integer feature ID to a clustered primary key; geometry uses a 5%-padded staged extent and geography uses automatic grid tessellation. Core/CLI live integration passed on isolated MySQL 8.4, MariaDB 11.4, and SQL Server 2022, including negative mixed-SRID write checks on both MySQL-family engines. Oracle remains limited to create mode; append/overwrite spatial-index creation is still open. Installed GUI clicks remain unverified. See [test report](test-report.md#2026-11-22-mysql-mariadb-and-sql-server-spatial-index-opt-in) and the [capability matrix](gis-database-capability-matrix.md).

## 2026-11-22 Oracle spatial-index follow-up

Oracle indexed overwrite is implemented by creating the replacement table's metadata and domain index on staging, then renaming it into place and verifying the index remains VALID. Oracle indexed append reuses and maintains an existing VALID domain index only when its SRID/X-Y metadata matches and the staged source extent fits within the registered bounds; out-of-bounds append fails before row writes. Appending with the option to a target without an index remains unsupported. Isolated Core/CLI integration passed create, indexed append, overwrite, failed-overwrite preservation and cleanup. The desktop checkbox is enabled for Oracle overwrite and append with mode-specific guidance; installed GUI clicks are not verified. See the [progress entry](progress.md#2026-11-22-oracle-spatial-index-append-and-overwrite), [test report](test-report.md#2026-11-22-oracle-indexed-append-and-overwrite-acceptance), and [capability matrix](gis-database-capability-matrix.md).

## 2026-11-22 MySQL/MariaDB and SQL Server indexed overwrite

MySQL/MariaDB and SQL Server spatial-index opt-in now supports create and overwrite, not append. Overwrite builds the replacement index on the staging table, verifies index metadata after the table swap, and deletes the prior table only after verification. MariaDB's SRID CHECK and SQL Server's clustered primary key are included in post-swap verification. Failed verification triggers a rollback attempt; if that also fails, the previous table backup is left in place and its name is reported. Live Core/CLI overwrite acceptance passed for MySQL, MariaDB, SQL Server geometry and geography; cleanup was zero. The desktop selector is available in create and overwrite modes; installed GUI interaction remains unverified. See [progress](progress.md#2026-11-22-mysqlmariadb-and-sql-server-spatial-index-overwrite), [test report](test-report.md#2026-11-22-mysqlmariadb-and-sql-server-indexed-overwrite-acceptance), and the [capability matrix](gis-database-capability-matrix.md).
