# Docker testing

Docker Engine 29.9.2 is available. A read-only inspection found other projects' PostgreSQL and MongoDB containers running on loopback-bound ports; those containers and their data are outside this project and are not test targets. The cached `postgres:16-alpine` image is about 419 MB. Host memory observation was 31.3 GB total and 8.4 GB free at inspection time.

The authorized `postgis/postgis:16-3.6` image is running as project container `db-studio-postgis-test`, bound only to `127.0.0.1:25432`, with its own persistent project volume and credentials in ignored `docker/.env`. Port 15432 and all unrelated containers remain outside this project. The service was used for the five-format GIS integration and column-metadata checks.

MySQL 8.4 and MariaDB 11.4 were explicitly authorized and are running as `db-studio-mysql-test` and `db-studio-mariadb-test`, bound only to `127.0.0.1:23306` and `127.0.0.1:23307`, with separate named volumes. Both passed Compose health checks. Before startup, Docker reported 16 CPUs, 15.3 GiB available to the engine and 50.7 GiB free on C:; the selected ports were not listening and neither image was cached. Credentials are generated locally in ignored `docker/.env` and never printed by the integration script.

`pnpm run test:integration:sql` passed on MySQL 8.4.13 and MariaDB 11.4.13. For each engine it verified the connection test, database listing, table/view listing, three-column metadata, parameterized Chinese insert/select, CSV/JSON/XLSX table round trips with SQL NULL preservation, and multi-batch rollback. The script cleans up only its random test tables and views.

The authorized official `mongo:7` service runs as `db-studio-mongodb-test` on `127.0.0.1:27018` with its own `mongodb-test-data` volume. The container passed its authenticated Compose health check; the server reports MongoDB 7.0.45. `pnpm run test:integration:mongodb` verified document browsing/query, Aggregate, JSON/EJSON import/export, ObjectId preservation, GeoJSON FeatureCollection conversion/round trip, `2dsphere` index create/list, and a `$geoWithin` query. MongoDB credentials are generated in ignored `docker/.env`; the script does not print them. It creates uniquely named collections in the project test database.

SQL Server Developer was explicitly authorized with `ACCEPT_EULA=Y`, project-specific storage, and loopback port `127.0.0.1:21433`. The 2.35 GB Microsoft image is running and healthy. `pnpm run test:integration:sqlserver` passed connection, database/schema/table/view and column browsing, parameterized Chinese query, CSV/JSON/XLSX table round trips, NULL preservation and transactional batch rollback. Its SA password is held only in ignored `docker/.env`.

The latest PostgreSQL/PostGIS rerun on port `127.0.0.1:25432` passed CSV/JSON/XLSX table round trips and the five GIS-format round trips using the separate vcpkg GDAL 3.12.2 candidate with Expat and LIBKML. `pnpm run test:integration:postgis-multilayer` confirmed that multi-layer GeoPackages require a valid source-layer choice and import only the selected layer. `pnpm run test:integration:postgis-cancel` cancelled a 200,000-feature import and export at 10%; the import transaction rolled back its destination table, and export removed its partial output and staging directory. `pnpm run test:integration:gis-dimensions` also passes: Shapefile and GeoPackage retain PointZM, GeoJSON/KML report M loss, and TAB reports Z/M loss. GIS test scripts discover GDAL/PROJ data beside `DBSTUDIO_GDAL_BIN`. Temporary SQL objects and GIS output files use unique names under the isolated project test database and .cache.

Oracle AI Database 26ai Free (23.26.3.0.0) is running in the authorized project-specific container on `127.0.0.1:21521`, using the dedicated volume and the accepted Oracle Free Use Terms. The live smoke passed connection, schema/object/column listing, bound query, version reporting, and CSV/JSON/XLSX round trips. Its first run revealed and led to a fix for a repeated positional bind in Oracle table/view listing.

Do not print or commit `docker/.env`. The integration script reads it locally and does not write credentials to its output. Keep the service available while project integration work continues; remove the test container only when the test environment is no longer needed, retaining its project data volume unless separately instructed.
