# GIS design

`packages/gis` owns vector metadata and file operations. It invokes GDAL/OGR as a separate executable and does not import a database driver. `packages/database` owns database connections and SQL. PostGIS file transfer is the explicit bridge between the two services.

The first service supports OGR metadata inspection, format conversion, and PostgreSQL/PostGIS import/export commands. Metadata inspection uses `ogrinfo -json -ro -so -al`; conversions use `ogr2ogr`. The API returns layer names, fields, geometry type, CRS, extent and feature count when OGR provides them. Inspection checks common Shapefile sidecars (`.shx`, `.dbf`, `.prj`/`.qpj`) and MapInfo TAB data files (`.dat`, `.map`), returns missing-file warnings with metadata, and appends the warnings when OGR cannot open an incomplete dataset.

For a requested coordinate transformation, a dataset without a source CRS must be paired with `--source-crs`; a target CRS is applied with OGR's transformation options. This changes coordinates through PROJ rather than only relabeling SRID. Existing output paths are rejected. Import defaults to create-only; append and overwrite are explicit modes.

Streaming progress is exposed from OGR's progress output. Larger files are processed by GDAL rather than materialized as Node.js feature arrays. Imports select one source layer; a multi-layer dataset requires an explicit `--layer` in the CLI or a choice in the desktop import form. The selected layer determines feature counts, fields and CRS checks. Imports use a dataset transaction, and cancellation rolls it back. File exports stage beside their destination and remove temporary files after failure or cancellation. Operation reports include status, feature counts when OGR can provide them, and bounded failure samples.

Import and export both accept per-field mappings. A mapping can rename an attribute and cast it to String, Integer, Integer64, Real, Date, Time or DateTime; OGR SQL quotes identifiers and carries the geometry field through the projection. Import validates source names and duplicate target names before starting. Export first reads the selected PostGIS table through OGR so primary-key FIDs and geometry columns are not offered as ordinary attributes. A failed cast aborts the PostGIS dataset transaction or staged file export.

The CLI uses repeatable `--field-map source=target` and `--field-type source=type` options. The desktop import form edits source fields directly; export first reads the PostGIS schema and then edits output names and types. Conversion reports include format constraint warnings for Shapefile, MapInfo TAB, KML and GeoJSON. These warnings describe known type, field-width or CRS constraints; they do not claim that every operation loses data. OGR errors are reported per operation; a detailed per-feature error list is not available.

The reusable geometry fixture covers Point, MultiPoint, LineString, MultiLineString, Polygon, MultiPolygon, GeometryCollection, null geometry and a self-intersecting invalid polygon. The live PostGIS integration checks every geometry class, invalidity/null preservation, then exports all nine features back through GeoPackage and GeoJSON.
